# واثق — نموذج عقد تداول USDT مقابل الدينار

هذه حزمة تطوير أولية تضيف عقدًا منفصلًا `WathiqUSDTP2PEscrow.sol` واختباراته. لم يتم استبدال العقد القديم حتى لا تتعطل الاختبارات الحالية أو التوافق السابق.

## منطق الصفقة
1. بائع USDT ينشئ الصفقة ويودع USDT في العقد. عنوان المشرف الموثوق يُحدد عند نشر العقد، ولا يستطيع البائع اختياره لكل صفقة.
2. المشتري يحوّل الدينار الليبي خارج البلوكشين ثم يبلّغ عن إرسال الدفع.
3. البائع يؤكد وصول الدينار، فيحرّر العقد USDT للمشتري.
4. إذا حدث نزاع، تتوقف التسوية ويبتّ المشرف المعيّن في الصفقة: تحرير USDT للمشتري أو إرجاعه للبائع.
5. إذا انتهت المهلة دون بلاغ من المشتري، يستطيع البائع استرجاع USDT. بعد بلاغ الدفع لا يوجد استرداد تلقائي.

## التثبيت داخل المستودع
انسخ الملفين إلى المسارين التاليين داخل نسخة المستودع على جهازك:
- `contracts/WathiqUSDTP2PEscrow.sol`
- `test/WathiqUSDTP2PEscrow.test.js`

ثم شغّل اختبارات المشروع من بيئة Node.js مدعومة:
```bash
npm test
```
أو شغّل الاختبار الجديد فقط حسب سكربت Hardhat الموجود في المشروع:
```bash
npx hardhat test test/WathiqUSDTP2PEscrow.test.js
```

## تحذيرات لا بد منها
- هذا نموذج أولي غير مدقق أمنيًا، وليس جاهزًا للأموال الحقيقية.
- `MockUSDT` للاختبار فقط، وليس USDT حقيقيًا.
- العقد لا يستطيع معرفة أن تحويل الدينار وصل فعليًا؛ بلاغ المشتري ليس دليلًا. يجب أن يتحقق المشرف من التحويل عبر مصدر موثوق خارج السلسلة، ويحفظ الإيصالات والبيانات الشخصية في تخزين خاص وآمن، ولا يضعها على البلوكشين.
- المشرف المعيّن في الصفقة يملك قرار النزاع لتلك الصفقة؛ لذلك يُحدد عنوان المشرف عند نشر العقد ولا يمكن تغييره في هذه النسخة؛ يجب اختيار عنوان مضبوط وحماية مفتاحه، وتسجيل قراراته، ووضع سياسة اعتراض وتشغيل واضحة.
- يجب مراجعة حالات التجميد الطويل، وهوية الأطراف، وآلية تغيير المشرف، والرسوم، والتوافق مع رمز USDT المستهدف، وإجراء تدقيق مستقل قبل أي إطلاق.
