# خارطة الطريق نحو أموال حقيقية — Production Roadmap

هذه الوثيقة تتبّع كل خطوة مقترحة لتحويل «واثق | Wathiq Escrow» من منتج
مكتمل الوظائف إلى خدمة تنقل أموالًا حقيقية، وحالة كل خطوة بصدق.
القاعدة الحاكمة: **لا أموال حقيقية قبل اكتمال قسمَي الضمان والقانون.**

## ١) البرمجة — Code

| الخطوة | الحالة |
|---|---|
| عقود ضمان BNB + USDT (تصويت 2 من 3، سحب Pull، ردّ بعد 30 يومًا) مع اختبارات 28/28 | ✅ منجزة |
| خادم: حسابات، عروض، دورة صفقات كاملة، إدارة، PostgreSQL | ✅ منجزة |
| تطبيق أندرويد + موقع ويب بكل وظائف الصفقات | ✅ منجزة |
| إثبات التمويل على السلسلة: الخادم يتحقق من معاملة `createDeal` (المرسل، الأطراف، المبلغ، حدث DealCreated) عبر JSON-RPC قبل اعتماد التمويل — `POST /api/deals/:id/link-chain` | ✅ منجزة (تُفعَّل بضبط `CHAIN_RPC_URL` و`USDT_ESCROW_ADDRESS`) |
| عناوين محافظ للمستخدمين (`PATCH /api/auth/me`) أساسًا للتحقق على السلسلة | ✅ منجزة |
| رقابة الإدارة على الصفقات (`GET /api/admin/deals` + قسم في لوحة الإدارة) | ✅ منجزة |
| توقيع المعاملات من داخل التطبيق (محفظة مدمجة أو WalletConnect) بدل لصق تجزئة المعاملة | ⬜ لاحقًا — بعد نشر Testnet |
| مفهرس أحداث (Indexer) يزامن حالة العقد تلقائيًا بدل الربط اليدوي | ⬜ لاحقًا |

## ٢) النشر — Deployment (بيد مالك المشروع فقط)

| الخطوة | الحالة |
|---|---|
| نشر العقود على BSC Testnet عبر GitHub Actions بمفتاح محفظة اختبار في أسرار المستودع (`DEPLOYER_PRIVATE_KEY`) — انظر `TESTNET_DEPLOYMENT.md` | ⬜ بانتظار المالك |
| ضبط عناوين العقود و`CHAIN_RPC_URL` و`USDT_ESCROW_ADDRESS` في إعدادات Render | ⬜ بعد النشر |
| إعادة نشر خدمة الـAPI على Render (Manual Deploy) بعد أي تغيير خادم | ⬜ عند الحاجة |
| تجربة دورة كاملة بأموال اختبار على Testnet من الموقع والتطبيق | ⬜ بعد النشر |
| استضافة إنتاج مدفوعة (الخطة المجانية تنام)، نسخ احتياطي مجدول، مراقبة وتنبيهات | ⬜ قبل الإطلاق الحقيقي |

## ٣) الضمان الأمني — Assurance (جهات خارجية)

| الخطوة | الحالة |
|---|---|
| تدقيق أمني مستقل للعقود الذكية من شركة متخصصة + إصلاح الملاحظات + إعادة فحص | ⬜ لم يبدأ — شرط صارم قبل أي مبلغ حقيقي |
| اختبار اختراق للخادم والتطبيق | ⬜ لم يبدأ |
| مفاتيح الإدارة/النشر في محفظة متعددة التوقيع (Multisig) | ⬜ قبل Mainnet |
| برنامج مكافآت ثغرات بعد الإطلاق | ⬜ لاحقًا |

## ٤) القانون والامتثال — Legal (الأكبر فعليًا)

| الخطوة | الحالة |
|---|---|
| كيان قانوني (شركة) وحسابات منفصلة لأموال العملاء | ⬜ لم يبدأ |
| ترخيص نشاط دفع/وساطة ضمان، أو شراكة مع جهة مرخّصة تحمل الأموال | ⬜ لم يبدأ |
| برنامج KYC/AML: تحقق هوية، فحص عقوبات، مراقبة معاملات، حفظ سجلات | ⬜ لم يبدأ |
| رأي محامٍ ليبي مختص بالقطاع المالي — موقف المصرف المركزي من العملات الرقمية تحذيري ووضعها القانوني غير محسوم | ⬜ لم يبدأ — قبل أي نشاط داخل ليبيا |
| شروط استخدام وسياسة فضّ نزاعات ملزمة ومسؤوليات موثقة | ⬜ لم يبدأ |

## ٥) الإطلاق — Launch

الترتيب الملزم: Testnet حيّ ← تدقيق أمني ← مسار قانوني/شريك مرخّص ←
Mainnet بسقوف صغيرة جدًا تُرفع تدريجيًا مع مراقبة كاملة.
أي قفز فوق خطوة من القسمين ٣ و٤ يعرض أموال المستخدمين ومالك المشروع
لمخاطر لا يمكن التراجع عنها.
